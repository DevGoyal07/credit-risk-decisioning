# Credit-Risk Decisioning — Probability of Default with Calibrated Scores & Reason Codes

A production-shaped credit-risk model on the **Home Credit Default Risk** data: it joins a
client's full credit history across multiple tables, predicts **probability of default (PD)**,
**calibrates** that score into a real probability, turns it into an **approve / refer / decline**
decision via an expected-loss policy, and emits **adverse-action reason codes** for every decline.

> Built to mirror how a card issuer actually decisions credit — relational feature engineering,
> ranking, calibration, policy cutoff, and explainability — not "AUC on a single Kaggle table."

---

## Why this shape

Most student credit projects are "logistic regression on the UCI German-credit set, AUC 0.78."
That reads as copied. Real issuer decisioning has four parts this project keeps:

1. **Rank** defaulters using a client's whole history — application + bureau + prior loans +
   installment behaviour — aggregated across one-to-many tables.
2. **Calibrate** the score so `0.30` means a genuine 30% default chance — required for expected loss.
3. **Decide** with a policy cutoff that trades approval rate against losses (an actual business curve).
4. **Explain** each decline with reason codes (the ECOA / Reg B "adverse action" requirement) —
   and because the features are named, the reasons read in plain language.

## Pipeline

| Stage        | File                  | What it does                                                                                                              |
| ------------ | --------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Data         | `src/data.py`         | Load the Home Credit tables                                                                                               |
| Features     | `src/features.py`     | **Relational aggregation**: bureau / previous / installments / POS / card → one row per client, plus affordability ratios |
| Train        | `src/train.py`        | LightGBM (a GBM) with 5-fold CV; saves honest out-of-fold predictions                                                     |
| Calibrate    | `src/calibrate.py`    | Isotonic calibration → trustworthy PD; reliability curve                                                                  |
| Policy       | `src/policy.py`       | PD → APPROVE/REFER/DECLINE; approval-vs-bad-rate curve; profit-optimal cutoff                                             |
| Reason codes | `src/reason_codes.py` | SHAP attribution → plain-language adverse-action reasons per applicant                                                    |
| Evaluate     | `src/evaluate.py`     | AUC, Gini, KS, Brier → `reports/results.md`                                                                               |
| Serve        | `serve/score.py`      | One applicant in → PD + decision + reason codes out (the live demo)                                                       |

## Dataset

**Home Credit Default Risk** (Kaggle). Multi-table and named-feature, so the feature engineering
is visible and the reason codes are human-readable. Put the CSVs under `data/homecredit/`:
`application_train.csv`, `application_test.csv`, `bureau.csv`, `previous_application.csv`,
`installments_payments.csv`, `POS_CASH_balance.csv`, `credit_card_balance.csv`.

> Relevance note for an Amex application: this is consumer-credit default risk end to end —
> the same problem and the same skills as Amex's credit-decisioning org. A natural "next step"
> line is validating the same pipeline on statement-level issuer data.

## Run it

```bash
python -m venv venv && venv\Scripts\activate     # Windows
pip install -r requirements.txt
# put the Kaggle CSVs under data/homecredit/

python -m src.data        # sanity-check table shapes
python -m src.train       # relational features + CV + out-of-fold predictions
python -m src.calibrate   # PD calibration + reliability plot
python -m src.policy      # approval/loss curve + profit-optimal cutoff
python -m src.evaluate    # writes reports/results.md
python -m serve.score     # score a single applicant end to end
```
